## Learned User Preferences

- Prefer automated per-push releases driven by GitHub Actions' built-ins over hand-bumped semver tags. Use `github.run_number` as the build number and let GitHub's `/releases/latest` endpoint track "current" — never hand-maintain a mutable `latest` tag.
- Prefer small in-tree subprocess wrappers (`os/exec` + `encoding/json`) over adopting SDKs whose surface area exceeds the need. `severity1/claude-agent-sdk-go` was rejected specifically because it doesn't expose `claude -p --output-format json --json-schema`.
- End-to-end plugin tests belong in a local script (`scripts/test-plugin.sh`), not in CI.
- When GitHub Actions emit Node runtime deprecation warnings, bump the action versions; do not ignore or suppress with env vars.
- When documenting or shipping tools for agent consumption, emit structured JSON on stdout, diagnostics on stderr; no TUIs, prompts, or colored output.

## Learned Workspace Facts

- `main` is the release. Every push to `main` triggers `.github/workflows/release.yml`, which builds linux/darwin × amd64/arm64 (4 targets) and publishes an immutable `v0.1.${{ github.run_number }}` release (tag carries the `v` prefix so Go's module proxy treats it as semver; the binary's printed version string is `0.1.<n>` without the `v`, embedded via `-ldflags -X main.version=0.1.<n>`). Releases are marked `make_latest: true`. Because tree-sitter is CGo, all targets build with `CGO_ENABLED=1`: linux cross-compiles from one ubuntu runner via `zig cc` (static musl), darwin builds natively on `macos-latest` (zig lacks the macOS SDK that Go's `-lresolv` needs). FreeBSD is intentionally dropped — `go-tree-sitter` has no freebsd support (`undefined: dupeFD`), so it cannot build. Windows is intentionally unsupported.
- Each release carries two asset shapes, both covered by `checksums.txt`: `slop-cop_<version>_<os>_<arch>.tar.gz` archives (consumed by the Homebrew cask and the binrun descriptor) and bare `slop-cop_<os>_<arch>` binaries. The plugin resolves its binary through [binrun](https://github.com/yasyf/binrun): `bin/slop-cop` is a committed symlink to the `scripts/install-binary.sh` shim (rendered from the cc-skills `binrun-shim` fragment), which locates the `binrun` runner and execs the version-exact release pinned in the committed `bin/slop-cop.binrun` descriptor, downloading and caching it once. `descriptor/slop-cop.binrun.tmpl` is the template `scripts/render-descriptor.sh` (rendered from the `render-descriptor` fragment) fills at release time. The `descriptor` job in `release.yml` moves `bin/slop-cop.binrun` and `.claude-plugin/plugin.json` to the release tag together, gated on agreement, and the CI `agreement` job re-asserts `plugin.json` version == descriptor `version.static` on every push. Callers resolve `bin/slop-cop` first, `$PATH` second. Never require users to install Go.
- Go toolchain is pinned to 1.26.2 via `.tool-versions` (asdf). Run `asdf install` in the repo root.
- LLM calls run the `claude` CLI through `github.com/yasyf/spawnllm/go` (pinned to an exact `go/vX.Y.Z` tag — `@main` and pseudo-versions do not compile, the embedded WASM blob ships only on release tags). slop-cop never holds an Anthropic API key; it rides the user's `claude` CLI subscription. spawnllm auto-retries transient failures (529/rate-limit/5xx) up to 5 attempts with backoff. `RunSchema` sets `UseHostConfig: true` because isolated mode seeds credentials from `account.json`/`credentials.json`, neither of which exists when `claude` keeps its login in the macOS keychain — and pairs it with a scratch `Dir` so the analysed document's own project `CLAUDE.md` cannot reach the detector prompt. It replaces the system prompt rather than appending: appending leaves Claude's agent framing in place and the model answers conversationally instead of performing the task.
- Violation `startIndex` / `endIndex` are UTF-8 byte offsets, not UTF-16 code units as in the upstream JS. Preserve this invariant in detectors and consumers.
- `detectNegationPivot` uses a hand-rolled two-sentence backreference because Go's RE2 `regexp` has no `\2`. Do not "fix" it by introducing backreferences.
- `internal/detectors/word_patterns_test.go` mirrors the upstream Vitest suite (201 subtests). Keep this parity when changing detector behavior.
- The rule catalogue, detectors, word lists, and LLM prompts derive from `awnist/slop-cop`, which was unlicensed at fork time. The Go source is MIT; derived content provenance and compliance guidance live in `NOTICE`. Consult it before broadening use.
- LLM analysis is controlled by `--llm-effort=off|low|high|auto` (default `auto`). `off` = client-side only. `low` = sentence tier (Claude Haiku, 11 extra rules, chunked around 4000 chars). `high` = sentence + document tiers (Haiku + Sonnet; +4 document rules). `auto` resolves to `high` whenever the `claude` CLI is on `$PATH`, else `off` — the plugin-env gate was removed, so the tiers auto-enable in CI too. Sugar aliases: `--llm` = `--llm-effort=low`, `--llm-deep` = `--llm-effort=high`; explicit `--llm-effort` wins over aliases, `--llm-deep` wins over `--llm`. Auto-resolved passes fail *open* (failure reported under `llm.<tier>.error`, client-side report still returned); explicit effort levels hard-fail with exit code 3.
- The rule catalogue is two layers. `internal/rules/rules.go` holds `Slop` (the 48 ported rules; its literals and `internal/detectors/word_patterns.go` are the awnist provenance boundary recorded in NOTICE and must stay byte-untouched), and `internal/rules/base.go` holds `Base` (9 original plain-language rules, category `base`) plus the composed `All` — slop-first, because `buildRulePrompt` numbers rules by position. 57 rules total: 42 client-side, 11 sentence-tier, 4 document-tier. `--standard=all|slop|base` selects layers and filters rules *before* the LLM prompt is built; `--standard=slop` reproduces pre-base-layer output byte-for-byte, which is pinned by a golden test and is the release gate for any change here. Note `false-range` carries an `LLMTier` with `RequiresLLM: false` (upstream data, deliberately not fixed), so count LLM rules by `RequiresLLM`, never by a bare `LLMTier`.
- The base layer is deliberately quiet: it drops any rule that conflicts with a slop rule rather than reconciling, so a semicolon ban, vertical-list rules, contractions, and all procedural rules were cut on measurement. `DetectPlainWord` is a sibling detector that emits the *existing* `elevated-register` rule ID, which is why 43 client-side detector functions produce only 42 client-side rules, and why `Deduplicate` runs unconditionally.
- `slop-cop check --lines` restricts the report to violations whose span *begins* within a 1-based inclusive line range (`50:80`, `50:`, `:80`, or a bare `50`). Detectors and the LLM passes still run over the full document for context; only the emitted violations are filtered (start-line attribution, so a document-level span like `staccato-burst` that begins at the top doesn't leak into every range). Parsing/filtering live in `cmd/slop-cop/lines.go`. Built for agents linting just the lines an edit touched.
- Plugin manifests live at `.claude-plugin/` (Claude Code) and `.cursor-plugin/` (Cursor); keep both in sync when editing skill or plugin metadata. The active skill is `skills/slop-cop-prose/SKILL.md`.
- Plugin verification runs locally via `scripts/test-plugin.sh`, which spawns `claude -p --plugin-dir` against the checkout. It is intentionally not part of CI.
- `slop-cop check` has a language-aware masking pipeline controlled by `--lang=auto|text|markdown|html|jsx|tsx|ts|js` (default `auto`, which picks by file extension; stdin defaults to `text`). Each mode runs an analyzer that masks non-prose bytes before detectors run — the invariant is `len(masked) == len(src)` with newlines preserved, so byte offsets in violations still index the original input. `markdown` uses goldmark; `html` uses `golang.org/x/net/html`; the four JS/TS variants use tree-sitter (`tree-sitter-javascript` for js/jsx, `tree-sitter-typescript` for ts/tsx). tree-sitter adds a CGo dependency — cross-compiles need the relevant toolchain. The shared contract lives at `internal/lang/Analyzer`; language packages register themselves via `init()`. Each mode also runs a mode-specific suppressions pass (e.g. `dramatic-fragment` in markdown headings, JSDoc blocks; `staccato-burst` across consecutive list items).
